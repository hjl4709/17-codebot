3.1 사전 학습

빈칸 채우기를 수만 번 반복하기

📖 비유

긴 글을 한 칸씩 밀어서 "다음 글자는?"을 계속 묻는 빈칸 채우기 문제집을 통째로 풀게 하는 것과 같습니다. 정답은 이미 원문에 있으니, 예측이 틀릴 때마다 모델 내부 값을 살짝씩 정답 쪽으로 고칩니다.

# 입력 x, 정답 y는 한 칸씩 밀린 같은 토큰열
x = tokens[i   : i+context_len]
y = tokens[i+1 : i+context_len+1]

logits = model(x)
loss = cross_entropy(logits, y)   # 예측과 정답의 차이
loss.backward(); optimizer.step() # 파라미터를 조금씩 수정

이 과정을 max_iters(예: 20,000)번 반복하며 손실(loss)이 점점 줄어드는 것을 확인합니다.

3.2 텍스트 생성

온도(temperature) 다이얼로 창의성 조절

🌡️ 비유

온도를 0으로 두면 항상 가장 확률 높은 답만 고르는 모범생이 되고 (결정적, argmax), 온도를 높이면 확률에 따라 무작위로 뽑아 더 즉흥적이고 다양한 답을 냅니다.

for _ in range(max_new_tokens):
    logits = model(ids)[:, -1, :]              # 마지막 위치의 예측
    if temperature == 0:
        next_id = logits.argmax(dim=-1)         # 가장 확실한 답만
    else:
        probs = softmax(logits / temperature)
        next_id = torch.multinomial(probs, 1)   # 확률적으로 샘플링
    ids = torch.cat([ids, next_id], dim=1)      # 한 토큰씩 이어붙여 생성
3.3 SFT를 위한 데이터 포맷

모범 답안집으로 과외 받기

🎓 비유

사전 학습이 "다독"이라면, SFT(지도 파인튜닝)는 "질문엔 이렇게 답하세요"라는 모범 답안집으로 진행하는 과외 수업입니다. 정해진 형식(Instruction → Response)을 반복해서 보여주면 모델이 대화의 틀과 태도를 학습합니다.

### Instruction:
Hello

### Response:
Hello. What can I help you with?<|endoftext|>

이 포맷(Alpaca 스타일)으로 각 질문-답변 쌍을 토큰화해 학습 데이터로 사용합니다.

SFT 손실 마스킹 — 질문은 베끼고, 답만 채점

✏️ 비유

시험 답안지에서 "문제" 부분은 그대로 옮겨 적고 채점하지 않고, "답" 부분만 채점하는 것과 같습니다. 프롬프트(질문) 구간의 레이블을 -100으로 마스킹해 손실 계산에서 제외하면, 모델이 질문을 외우는 게 아니라 "어떻게 답할지"를 배우게 됩니다.

prompt_ids   = tokenizer.encode(instruction_text)
response_ids = tokenizer.encode(response_text)

ids    = prompt_ids + response_ids
labels = [-100] * len(prompt_ids) + response_ids   # 프롬프트 구간은 채점 제외

loss = cross_entropy(logits, labels, ignore_index=-100)

3.5

SFT만으론 부족하다 — 강화 학습이 필요한 이유

운동선수가 코치의 시범(SFT)만 보고는 실력이 한계에 부딪히듯, 모델도 정해진 예시를 모방하는 것만으로는 스스로 시행착오를 거쳐야 느는 능력에 닿지 못합니다.

3.5 강화 학습과 언어 모델

스스로 풀어보고, 맞으면 칭찬받기

3.6 정책 경사법

강아지 훈련처럼: 잘하면 그 행동을 더

🐶 비유

강아지가 우연히 "앉아"를 했을 때 간식을 주면, 강아지는 그 행동을 더 자주 하게 됩니다. 정책 경사법(policy gradient)도 똑같습니다 — 모델이 생성한 답이 보상(reward)이 높았다면 그 답을 낼 확률을 높이고, 보상이 낮았다면 확률을 낮추는 방향으로 파라미터를 조정합니다.

3.7 베이스라인

절대 점수가 아니라 "평균 대비"로 평가하기

📊 비유 — 반 평균

90점을 받아도 반 평균이 95점이면 그리 잘한 게 아니고, 90점이 반 평균이 60점인 데서 나왔다면 아주 잘한 것이죠. 베이스라인(평균 보상)을 빼서 "평균보다 얼마나 잘했는가" (advantage)로 평가하면 학습이 훨씬 안정적입니다.

rewards = [calculate_reward(gt, r) for r in responses]
advantages = rewards - rewards.mean()   # 그룹 평균 대비 상대 점수
3.8 오프-정책과 클리핑

변화 폭에 브레이크 걸기

🥗 비유 — 급격한 다이어트 방지

답을 생성한 "옛 모델"과 지금 갱신 중인 "현재 모델"이 조금씩 달라지는데(오프-정책), 한 번에 너무 크게 바뀌면 요요처럼 불안정해질 수 있습니다. 클리핑은 확률비(ratio)의 변화폭을 [1-ε, 1+ε] 범위로 제한해, 점진적이고 안전하게 조금씩만 바뀌도록 브레이크를 겁니다.

ratio = probs / old_probs                                   # 확률이 얼마나 변했나
clipped = torch.clamp(ratio, 1-epsilon, 1+epsilon) * advantages
objective = torch.min(ratio * advantages, clipped)           # 더 보수적인 쪽 선택
3.9 GRPO

그룹으로 여러 번 시도해보고 비교하기

GRPO(Group Relative Policy Optimization)는 하나의 문제에 대해 여러 개(group_size)의 답을 생성하고, 그룹 평균 대비 잘한 답의 확률은 높이고 못한 답은 낮춥니다.

# CodeBot 예제: 덧셈 문제 "3+5=" 처럼 정답이 명확한 과제
prompt = "### Instruction:\n3+5=\n\n### Response:\n"
ground_truth = 8

def calculate_reward(gt, response):
    predicted = int(찾은 마지막 숫자)
    return 1.0 if predicted == gt else 0.0   # 정답이면 1점, 아니면 0점

GRPO 학습 루프

1
문제 하나당 옛 모델로 8개(group_size)의 답을 각각 생성
2
각 답의 보상(정답 여부)을 계산
3
그룹 평균 대비 advantage 산출 (평균보다 잘했나?)
4
클리핑된 목적함수로 현재 모델을 여러 번 업데이트
5
옛 모델을 현재 모델로 갱신하고 반복 — 정답률이 점점 상승

SFT 학습에서 프롬프트(질문) 구간의 레이블을 -100으로 두는 이유는?
