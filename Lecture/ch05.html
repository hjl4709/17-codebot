5.1 RoPE (회전 위치 인코딩)

위치를, 벡터를 "돌려서" 표현하기

🧭 비유 — 시계 바늘

2장의 위치 인코딩은 단어 벡터에 위치 정보를 더하는 방식이었습니다. RoPE는 대신 Q, K 벡터를 위치에 비례하는 각도만큼 회전시킵니다. 시계 바늘이 시간이 지날수록 일정한 각도로 계속 돌아가듯, 토큰이 뒤로 갈수록 벡터도 조금씩 더 돌아갑니다. 두 벡터의 회전 각도 차이가 곧 "둘 사이의 거리"가 되어, 상대적 위치 관계가 자연스럽게 계산에 녹아듭니다.

angle = position * inv_freq          # 위치에 비례한 회전 각도
q_rot = q * cos(angle) - q_swap * sin(angle)  # Q, K를 회전
# 회전된 Q·K를 내적하면 "위치 차이"가 자동으로 반영됨

덧셈(절대 위치) 대신 회전(상대 위치)을 쓰면, 학습 때보다 더 긴 문장에도 비교적 잘 대응합니다.

5.2 SwiGLU

수도꼭지 두 개로 흐름을 정교하게 조절하기

🚿 비유

2장의 FFN은 하나의 통로로 정보를 흘려보냈습니다. SwiGLU는 두 개의 변환을 만들어 하나(V)는 "내용물", 다른 하나(W, SiLU 활성화 통과)는 "얼마나 흘려보낼지 정하는 밸브(게이트)" 역할을 하게 해서 둘을 곱합니다. 밸브가 있는 수도꼭지가 물의 양을 더 섬세하게 조절할 수 있는 것과 같습니다.

a = W(x)              # 밸브: 얼마나 통과시킬지
b = V(x)              # 내용물
gated = silu(a) * b   # 밸브를 통과한 만큼만 내용물이 흐름
out = O(gated)

같은 파라미터 예산에서 성능이 더 좋다고 알려져, LLaMA 등 최신 모델 다수가 채택했습니다.

5.3 RMSNorm

레시피에서 불필요한 단계 하나 생략하기

✂️ 비유

2장의 LayerNorm은 평균을 빼고(중심 맞추기) → 표준편차로 나누고(크기 맞추기) 두 단계를 거칩니다. RMSNorm은 평균을 빼는 단계를 생략하고 크기(제곱평균제곱근) 로만 나눠 스케일을 맞춥니다. 딱 필요한 만큼만 정규화해 계산이 더 가볍고, 실전에서도 성능 차이는 크지 않습니다.

// LayerNorm: (x - 평균) / 표준편차
// RMSNorm:    x / RMS(x)              ← 평균을 빼는 단계가 없음
rms = sqrt(mean(x**2) + eps)
out = gamma * x / rms
5.4 개선된 GPT 구현

세 부품을 조립해 StoryBot의 몸통을 완성

class Block(nn.Module):
    def __init__(self, embed_dim, n_head, ff_dim, rope):
        self.norm1 = nn.RMSNorm(embed_dim)              # ← RMSNorm
        self.attn  = MultiHeadAttention(..., rope=rope)  # ← RoPE 내장
        self.norm2 = nn.RMSNorm(embed_dim)
        self.ffn   = SwiGLU(embed_dim, ff_dim)            # ← SwiGLU

    def forward(self, x):
        x = x + self.attn(self.norm1(x))
        x = x + self.ffn(self.norm2(x))
        return x

2장의 GPT-2와 뼈대(잔차 연결 + 정규화 + 어텐션 + FFN)는 완전히 동일하고, 내부 부품만 더 효율적인 것으로 교체했다는 점이 핵심입니다.

5.5 KV 캐시

매번 처음부터 다시 확인하지 않는 웨이터

🧑‍🍳 비유

토큰을 한 개씩 생성할 때마다 지금까지의 모든 토큰을 처음부터 다시 어텐션 계산하면 매우 비효율적입니다. KV 캐시는 이미 계산해 둔 과거 토큰들의 Key와 Value를 메모해두고, 새로 생긴 토큰의 K·V만 추가로 계산해 이어 붙입니다 — 손님이 추가 주문을 할 때마다 이전 주문 전체를 다시 묻지 않고, 메모장에 새 주문만 한 줄 추가하는 웨이터와 같습니다.

if is_first_call:
    k_cache, v_cache = K, V                          # 프리필: 캐시 생성
else:
    k_cache = torch.cat([k_cache, K], dim=2)          # 디코드: 새 토큰만 추가
    v_cache = torch.cat([v_cache, V], dim=2)

5.6 정리

5장 핵심 요약

  • RoPE: 위치 정보를 벡터 "회전"으로 표현 → 상대적 거리 관계를 자연스럽게 반영
  • SwiGLU: 게이트가 달린 FFN → 정보 흐름을 더 정교하게 조절
  • RMSNorm: 평균 빼기를 생략한 가벼운 정규화
  • KV 캐시: 과거 토큰의 Key·Value를 재사용해 생성 속도를 크게 향상

QUIZ 1

RoPE가 위치 정보를 표현하는 방식은?

정답: 두 번째. 덧셈이 아니라 회전으로 위치를 표현해 상대적 거리 정보를 자연스럽게 담습니다.
QUIZ 2

KV 캐시를 사용하면 새 토큰을 생성할 때 다시 계산해야 하는 것은?

정답: 두 번째. 과거 토큰의 K, V는 캐시에 저장해 재사용하고, 새 토큰의 K, V만 계산해서 캐시에 이어 붙입니다.
