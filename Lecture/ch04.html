4.1 BPE 학습 개선 ① 중복 제거

같은 단어를 100만 번 세지 말고, "100만 번 있음"이라고 적어두기

📦 비유 — 재고 관리

텍스트에는 "the", "and" 같은 단어가 수십만 번 반복됩니다. 매번 똑같은 ID열을 처음부터 다시 스캔하는 대신, 사전 토큰의 종류와 등장 횟수만 기록해두면 훨씬 적은 계산으로 같은 결과를 얻을 수 있습니다 — 창고 관리인이 상자를 하나하나 세는 대신 "이 상자 1,000개 있음"이라고 재고표에 적어두는 것과 같습니다.

# 이전: 모든 위치를 매번 훑음
# 개선: (사전 토큰 → 등장 횟수) 로 압축해서 딱 한 번만 기록
pretoken_counts = defaultdict(int)
for pretoken in pretokenize(text):
    pretoken_counts[pretoken] += 1

ids_counts = {tuple(pt.encode("utf-8")): cnt for pt, cnt in pretoken_counts.items()}
# 병합 시 등장 횟수(count)만큼 가중치를 곱해서 집계 → 계산량 대폭 감소
4.2 BPE 학습 개선 ② 부분 갱신

안경을 잃어버렸을 때 온 집을 다 뒤지지 않기

🔍 비유

병합을 한 번 할 때마다 전체 데이터를 처음부터 다시 스캔하면 매우 느립니다. 대신 "이 쌍이 어느 단어들에 들어있었는지"를 미리 캐시(pair_to_ids)해두면, 병합 후 영향을 받은 단어들만 골라서 갱신할 수 있습니다 — 안경을 마지막으로 본 장소만 확인하면 되지, 집 전체를 다시 뒤질 필요는 없는 것과 같습니다.

pair_to_ids = defaultdict(set)  # 이 쌍이 등장하는 단어들의 캐시

4.4 BPE 학습 개선 ④ 병렬화

혼자 설거지 대신 여덟 명이 나눠서

🧑‍🍳 비유

조각 낸 데이터를 여러 프로세스(예: 8개)가 동시에 사전 토큰화하면, 이론상 8배 가까이 빨라집니다 — 설거지거리를 혼자 다 하는 대신 여덟 명이 나눠 맡아 동시에 처리하는 것과 같습니다.

4.5 토크나이저 평가

전문 사전은 전문 분야에서만 잘 맞는다

📖 비유

코드 전용으로 학습한 CodeBot 토크나이저를 이야기(story) 텍스트에 사용하면 압축률이 떨어집니다 — 요리 전문 사전을 문학 작품 번역에 쓰면 어색한 것과 비슷합니다. 토크나이저는 학습에 사용한 데이터와 비슷한 도메인에서 가장 잘 작동합니다.

sample_text = open("storybot/tiny_stories_train.txt").read()[:10000]

# StoryBot 전용 토크나이저(어휘 10,000개, 이야기로 학습)
storybot_tokenizer.encode(sample_text)   # 압축률 더 높음

# CodeBot 전용 토크나이저(어휘 1,000개, 코드로 학습)를 이야기에 사용
codebot_tokenizer.encode(sample_text)    # 압축률 더 낮음 (도메인 불일치)
4.6 BPE 인코딩 개선 ① 고속 병합

규칙집을 처음부터 끝까지 다 훑지 않기

📘 비유

1장의 인코딩은 학습된 병합 규칙 전부를 순서대로 적용했습니다(규칙이 10,000개면 10,000번 스캔). 개선된 방식은 지금 남아있는 인접 쌍들 중 "가장 먼저 배운 (우선순위가 높은) 쌍" 하나만 콕 찾아서 병합하고, 더 병합할 쌍이 없으면 즉시 멈춥니다 — 요리책 전체를 순서대로 다 읽는 대신, 지금 냉장고에 있는 재료로 만들 수 있는 "가장 먼저 배운 레시피"부터 바로 찾아 적용하는 것과 같습니다.

def get_merge_priority(pair):
    return merge_rules.get(pair, float('inf'))  # 없는 쌍은 최하위 우선순위

while len(ids) > 1:
    counts = count_pairs(ids)
    best_pair = min(counts, key=get_merge_priority)  # 우선순위가 가장 높은 쌍만 탐색
    if best_pair not in merge_rules:
        break                                     # 더 병합할 쌍 없으면 종료
    ids = merge(ids, best_pair, merge_rules[best_pair])
4.7 BPE 인코딩 개선 ② 대규모 데이터 처리

여러 트럭이 각자 창고 구역에 바로 적재하기

🏭 비유

전체 학습 데이터를 인코딩할 때도 파일을 청크로 나눠 여러 프로세스가 병렬로 처리합니다. 각 결과는 한곳에 모았다가 다시 합치는 대신, np.memmap(디스크와 직접 연결된 배열)의 자기 담당 구역에 곧바로 기록합니다 — 트럭마다 짐을 중앙 집하장을 거치지 않고 창고의 정해진 자리에 바로 내려놓는 것과 같아 메모리를 절약합니다.

arr = np.memmap(output_file, dtype=np.uint16, mode='w+', shape=(total_tokens,))

idx = 0
for cache_file in cache_files:            # 각 프로세스가 만든 조각 파일
    chunk_data = np.fromfile(cache_file, dtype=np.uint16)
    arr[idx : idx+len(chunk_data)] = chunk_data  # 디스크의 제자리에 바로 기록
    idx += len(chunk_data)
4.8 정리

4장 핵심 요약

  • 학습 최적화: 중복 제거(재고표) → 부분 갱신(영향받은 곳만) → 분할 처리(조각내어 읽기) → 병렬화(여러 일꾼)
  • 토크나이저는 학습 데이터의 도메인에 맞춰야 압축률이 좋다
  • 인코딩 최적화: 우선순위 기반 고속 병합 + 병렬·메모리맵 기반 대규모 인코딩
  • 원리(1장)는 그대로, 엔지니어링만 개선해 훨씬 큰 데이터를 다룰 수 있게 됨

QUIZ 1

"부분 갱신" 최적화의 핵심 아이디어는?

정답: 두 번째. pair_to_ids 캐시로 영향받는 단어만 찾아 갱신하면, 매번 전체 데이터를 다시 스캔하지 않아도 됩니다.
QUIZ 2

CodeBot용 토크나이저를 이야기(스토리) 텍스트에 쓰면 어떤 일이 벌어지나요?

정답: 두 번째. 토크나이저는 학습에 쓰인 데이터의 패턴에 최적화되어 있어, 다른 도메인 텍스트에는 상대적으로 비효율적입니다.
