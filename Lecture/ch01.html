컴퓨터는 숫자만 이해한다

✈️ 비유

외국에 가면 통역사가 내 말을 그 나라 언어로, 그 나라 말을 다시 내 말로 바꿔주죠. 토크나이저도 똑같습니다. "안녕"이라는 글자를 모델이 계산할 수 있는 토큰 ID(숫자)로 바꾸고(인코딩), 모델이 내놓은 숫자를 다시 사람이 읽을 글자로 바꿔줍니다(디코딩).

이 장에서는 이 통역사를 문자 단위 → 바이트 단위 → BPE 순서로 점점 똑똑하게 발전시킵니다.

1.1 문자 단위 토큰화

가장 단순한 방법: 글자 하나 = 번호 하나

파이썬의 ord()/chr()를 쓰면 글자마다 이미 정해진 유니코드 번호가 있습니다.

class CharTokenizer:
    def encode(self, text):
        return [ord(c) for c in text]

    def decode(self, ids):
        return ''.join([chr(i) for i in ids])

# "hello월드😁" → [104, 101, 108, 108, 111, 50900, 46300, 128513]
📕 비유

세상의 모든 글자마다 고유 번호가 이미 매겨진 초대형 사전을 그대로 쓰는 셈입니다. 문제는 이 사전이 이모지까지 포함해 10만 개가 훌쩍 넘는다는 것 — 모델이 다뤄야 할 "단어장"이 지나치게 커집니다.

1.2 바이트 단위 토큰화

기본 단위를 256개로 확 줄이기

UTF-8로 인코딩하면 어떤 문자든 0~255 사이의 바이트 값들의 조합으로 표현됩니다.

class ByteTokenizer:
    def encode(self, text):
        return list(text.encode("utf-8"))

    def decode(self, ids):
        return bytes(ids).decode("utf-8")

# '가' → b'\xea\xb0\x80' → [234, 160, 128]  (한 글자가 바이트 3개로!)
🧱 비유

레고 기본 블록 256종류만으로 세상 모든 것을 조립하는 것과 같습니다. 사전 크기는 딱 256개로 고정되어 깔끔하지만, 영어가 아닌 글자(한글, 이모지 등)는 여러 블록을 이어 붙여야 해서 문장이 훨씬 길어집니다.

방식어휘 크기한글 한 글자
문자 단위10만+ (사실상 무한)토큰 1개
바이트 단위256 (고정)토큰 3개
1.3 BPE 학습 알고리즘

자주 붙어다니는 짝을 새 토큰으로 승격

💬 비유

메신저에서 "ㅇㅋ", "생축"처럼 자주 쓰는 표현을 줄임말로 새로 만드는 것과 같습니다. BPE(Byte Pair Encoding)는 텍스트 안에서 가장 자주 붙어 나오는 바이트 쌍을 찾아 새로운 토큰 하나로 합치는 과정을, 원하는 어휘 크기가 될 때까지 반복합니다.

def count_pairs(ids):          # 인접한 쌍의 빈도 세기
    counts = defaultdict(int)
    for pair in zip(ids, ids[1:]):
        counts[pair] += 1
    return counts

def merge(ids, pair, new_id):    # 가장 빈번한 쌍을 새 ID로 교체
    ... (i, i+1)이 pair와 같으면 new_id 하나로 합치고, 아니면 그대로 둔다

BPE 학습 루프

1
텍스트를 바이트 ID열(0~255)로 변환
2
가장 자주 등장하는 인접 쌍을 찾음 max(counts, key=counts.get)
3
그 쌍에 새 토큰 ID(256, 257, …)를 부여하고 병합 규칙에 저장
4
전체 ID열에서 그 쌍을 새 ID로 교체
5
목표 어휘 크기에 도달할 때까지 2~4를 반복
# "Hello world! This is BPE training." → vocab_size=260 (병합 4번)
merge_rules = {(105, 115): 256,   # 'i'+'s' → 256
               (256, 32): 257,    # 256+' ' → 257 ("is ")
               (105, 110): 258,   # 'i'+'n' → 258
               (72, 101): 259}    # 'H'+'e' → 259

병합할 때마다 어휘가 1개씩 늘고, 텍스트를 표현하는 토큰 수는 점점 줄어듭니다 — 즉 압축됩니다.

1.4 BPE 인코딩과 디코딩

학습된 규칙으로 압축하고, 다시 풀어내기

인코딩: 학습 때와 같은 순서로 병합 규칙을 차례로 적용합니다.
디코딩: 각 토큰 ID가 어떤 바이트열이었는지 표(id_to_bytes)를 보고 이어붙인 뒤 UTF-8로 되돌립니다.

class BPETokenizer:
    def __init__(self, merge_rules):
        self.id_to_bytes = {i: bytes([i]) for i in range(256)}
        for (id1, id2), new_id in merge_rules.items():
            self.id_to_bytes[new_id] = self.id_to_bytes[id1] + self.id_to_bytes[id2]

    def decode(self, ids):
        combined = b"".join(self.id_to_bytes[i] for i in ids)
        return combined.decode("utf-8", errors="replace")
🗜️ 비유

zip 압축 프로그램과 비슷합니다. 병합 규칙표는 "압축 해제 사전" 역할을 해서, 어떤 토큰이 원래 어떤 바이트 조각들이었는지 보고 원문을 정확히 복원합니다.

1.5 특수 토큰 대응

"여기서 끝!"을 알려주는 도장

📄 비유

여러 문서를 이어 붙여 학습할 때, 문서와 문서 사이에 "끝" 도장을 찍어두지 않으면 모델이 서로 다른 글을 하나로 착각합니다. <|endoftext|>라는 특수 토큰이 그 도장 역할을 합니다.

  • 학습 전, 원문을 <|endoftext|> 기준으로 먼저 나눈 뒤 각 조각 안에서만 BPE 병합 진행 (문서 경계를 넘어서 병합되지 않도록)
  • 특수 토큰에는 전용 ID 하나를 별도로 배정 (병합 규칙과 무관하게 통째로 취급)
  • 인코딩 시 정규식으로 특수 토큰을 먼저 분리한 뒤, 나머지 부분만 BPE 인코딩
1.6 사전 토큰화

자르기 전에 재료부터 미리 손질하기

🍱 비유

김밥을 말기 전에 재료를 미리 알맞은 크기로 손질해두듯, BPE를 돌리기 전에 정규식으로 먼저 단어·공백·숫자·문장부호 단위로 큼직하게 잘라둡니다(사전 토큰화). 그래야 "dog."와 "dog!"처럼 의미상 무관한 조합이 하나의 토큰으로 이상하게 뭉치는 것을 막을 수 있습니다.

import regex as re
pattern = r"'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"
def pretokenize(text):
    return re.findall(pattern, text)  # GPT-2와 동일한 패턴

이후 BPE는 이렇게 나뉜 조각(pretoken) 안에서만 병합을 수행합니다.

1.8 토크나이저 평가

얼마나 잘 "압축"했을까?

토크나이저의 품질은 압축률(원문 바이트 수 ÷ 토큰 수)로 가늠할 수 있습니다.

byte_count = len(text.encode("utf-8"))
ids_count  = len(tokenizer.encode(text))
compression_ratio = byte_count / ids_count
# 예: 압축률 3.5배 → 평균 1토큰이 3.5바이트를 담당
📦 비유

압축 프로그램의 압축률과 똑같은 개념입니다. 압축률이 높을수록 같은 문장을 더 적은 토큰으로 표현할 수 있어, 모델이 한 번에 더 많은 내용을 "시야"에 담고 학습·추론 속도도 빨라집니다.

학습 초반에 만들어진 토큰(ID 256~)은 짧은 흔한 조합, 후반에 만들어진 토큰(ID 990~)은 코드에서 자주 쓰이는 긴 패턴(예: 함수 정의 구문)인 경향이 있습니다.

1.9 TinyCodes 인코딩

학습용 데이터를 통째로 숫자로 바꿔두기

tokenizer = BPETokenizer.load_from("codebot/merge_rules.pkl")
ids = tokenizer.encode(text, show_progress=True)

ids_array = np.array(ids, dtype=np.uint16)   # 어휘 1,000개 → 2바이트로 충분
ids_array.tofile("codebot/tiny_codes.bin")

전체 TinyCodes 텍스트를 한 번에 토큰 ID 배열로 바꿔 .bin 파일로 저장해두면, 3장의 사전 학습 때마다 매번 다시 인코딩할 필요 없이 바로 불러 쓸 수 있습니다.

1.10 정리

1장 핵심 요약

  • 문자 단위: 직관적이지만 어휘가 10만+ 로 지나치게 큼
  • 바이트 단위: 어휘 256개로 고정되지만 비영어권 텍스트가 길어짐
  • BPE: 자주 붙어 나오는 쌍을 반복적으로 병합해, 어휘 크기와 압축률 사이의 균형을 스스로 찾아냄
  • 특수 토큰으로 문서 경계를 표시하고, 사전 토큰화로 엉뚱한 병합을 방지
  • 이렇게 만든 토크나이저로 TinyCodes 전체를 인코딩해 다음 장(모델)의 재료를 준비
➡️ 다음 시간

2장 모델: 토큰 ID들을 받아 "다음 토큰"을 예측하는 어텐션과 트랜스포머 구조를 만듭니다.

QUIZ 1

바이트 단위 토큰화의 어휘 크기는 항상 몇 개인가요?

정답: 256개. UTF-8로 인코딩한 바이트 값은 항상 0~255 범위이므로 어휘 크기가 고정됩니다.
QUIZ 2

BPE 학습에서 매 단계마다 병합하는 대상은?

정답: 가장 자주 등장하는 인접 쌍. 이를 새 토큰 ID로 승격시키는 과정을 목표 어휘 크기까지 반복합니다.
