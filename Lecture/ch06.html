6.1 – 6.2 AdamW의 원리와 구현

관성 + 자동 브레이크가 달린 똑똑한 자전거

🚲 비유

기본 경사하강법(SGD)은 매 순간의 기울기만 보고 움직입니다. AdamW는 두 가지를 더 봅니다: ① 지금까지 움직여온 방향의 관성(1차 모멘트, m) — 언덕을 내려가던 방향으로 계속 가속. ② 각 파라미터별로 요동이 컸는지(2차 모멘트, v)를 보고 보폭을 자동으로 조절 — 울퉁불퉁한 길에서는 조심조심, 평탄한 길에서는 성큼성큼. 여기에 가중치가 너무 커지지 않도록 별도로 깎아내는 weight decay까지 더합니다.

m = beta1*m + (1-beta1)*grad         # 관성 (모멘텀)
v = beta2*v + (1-beta2)*grad**2      # 요동의 크기 (적응적 학습률)
m_hat, v_hat = m/(1-beta1**t), v/(1-beta2**t)   # 초반 편향 보정

# 파라미터 갱신 + 별도의 가중치 감쇠(decoupled weight decay)
p = p - lr * m_hat / (sqrt(v_hat) + eps) - lr * weight_decay * p
6.3 학습률 스케줄

급출발·급정거 없이 서서히 가속·감속

🚗 비유

자동차가 출발하자마자 최고 속도로 밟으면 위험하듯, 학습 초반부터 큰 학습률을 쓰면 불안정해질 수 있습니다. 워밍업(0 → 최대치로 서서히 가속)으로 부드럽게 출발한 뒤, 어닐링(최대치 → 0으로 서서히 감속)으로 목적지 근처에서 정교하게 수렴하도록 유도합니다.

def get_lr(it, max_lr, warmup_iters, max_iters):
    if it < warmup_iters:
        return max_lr * (it / warmup_iters)          # 워밍업: 0 → max_lr
    progress = (it - warmup_iters) / (max_iters - warmup_iters)
    return max_lr * (1.0 - progress)                # 어닐링: max_lr → 0
6.4 혼합 정밀도

대부분은 눈대중으로, 중요한 계산은 정밀하게

🧮 비유

숫자를 32비트(FP32)로 다루면 정확하지만 느립니다. 16비트로 계산하면 빠르지만, FP16은 표현 범위가 좁아 너무 크거나(70000 → inf) 너무 작은 값(1e-8 → 0)이 깨집니다. BF16은 범위는 FP32만큼 넓게 유지하면서 정밀도만 줄인 절충안입니다. 행렬곱처럼 규모가 큰 연산은 BF16(빠름)으로, 합계처럼 정밀도가 중요한 연산은 FP32로 자동 전환하는 것이 혼합 정밀도(autocast)입니다.

with torch.autocast(device_type=device, dtype=torch.bfloat16):
    b = a @ a    # 행렬곱: BF16으로 빠르게
    c = a.sum()  # 합계: 자동으로 FP32 유지 (정밀도 보호)

RLHF와 DPO — 사람의 "취향"을 직접 반영하기

사전 학습 + SFT를 마친 모델도 "더 재미있는 결말", "더 안전한 답변"처럼 정답이 하나로 딱 떨어지지 않는 취향은 배우지 못합니다. 이를 위한 두 가지 접근을 비교합니다.

RLHF vs DPO

🏆 비유 — 심사위원

RLHF: 먼저 "이게 더 나은 답이다"라는 채점 기준을 학습한 별도의 심사위원(보상 모델)을 키운 뒤, 그 심사위원 점수에 맞춰 GRPO 같은 강화 학습으로 연습합니다.
DPO: 심사위원을 따로 키우지 않고, "이 답(chosen)이 저 답(rejected)보다 낫다"는 비교 데이터만으로 곧장 그 선호를 반영하도록 모델을 직접 조정하는 지름길입니다.

RLHFDPO
구성 요소보상 모델 + RL 알고리즘선호 데이터(chosen/rejected)만
구현 복잡도높음 (두 단계)낮음 (지도학습과 유사)
6.8 DPO 구현

둘 중 더 마음에 드는 쪽에 투표하기

🗳️ 비유

같은 프롬프트에 대해 선호되는 답(chosen)과 덜 선호되는 답(rejected) 한 쌍이 주어지면, "학습 전 원본 모델(참조 모델)" 대비 chosen을 rejected보다 얼마나 더 선호하게 되었는지를 키워가는 방향으로 학습합니다. 원본과 비교하는 이유는, 모델이 너무 극단적으로 변하지 않게 붙잡아두는 닻 역할을 하기 때문입니다.

chosen_lp   = get_sequence_logprobs(model, chosen_ids)
rejected_lp = get_sequence_logprobs(model, rejected_ids)
ref_chosen_lp   = get_sequence_logprobs(ref_model, chosen_ids)    # 참조 모델(닻)
ref_rejected_lp = get_sequence_logprobs(ref_model, rejected_ids)

# 참조 모델 대비 "chosen을 더 선호하게 된 정도"
logits = beta * ((chosen_lp - rejected_lp) - (ref_chosen_lp - ref_rejected_lp))
loss = -logsigmoid(logits).mean()
6.9 정리

6장 핵심 요약

  • AdamW: 관성(모멘텀) + 파라미터별 보폭 자동 조절 + 별도의 가중치 감쇠
  • 학습률 스케줄: 워밍업(서서히 가속) + 어닐링(서서히 감속)
  • 혼합 정밀도: 대부분 BF16(빠름), 중요한 부분만 FP32(정밀)
  • LLM-as-a-Judge로 학습이 잘 되고 있는지 자동 평가
  • DPO: 별도 보상 모델 없이 chosen/rejected 비교만으로 "취향"을 직접 학습 → 사람 평가에서 DPO 모델의 승률 상승 확인

학습률 워밍업(warmup)을 두는 이유는?

정답: 두 번째. 학습률을 0에서 서서히 최댓값으로 올려 초반 불안정을 방지합니다.
QUIZ 2

DPO에서 "참조 모델(reference model)"과 비교하는 이유는?

정답: 두 번째. 참조 모델 대비 상대적인 선호 변화만 키우도록 해, 학습이 폭주하지 않게 닻 역할을 합니다.
