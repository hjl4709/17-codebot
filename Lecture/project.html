tokenizer.py의 진화 — 그리고 "재사용"

♻️ 비유

WebBot 폴더를 열어보면 tokenizer.py가 아예 없습니다. 코드를 또 복사해 넣는 대신, storybot.tokenizer를 그대로 가져다 씁니다 — 이미 검증된 최적화(4장)를 다시 만들 필요가 없기 때문입니다. 좋은 코드는 "또 짜는 것"이 아니라 "가져다 쓰는 것"이라는 소프트웨어 공학의 기본 원칙입니다.

# ch07/01_bpe_train.py — WebBot의 토크나이저 학습
from storybot.tokenizer import train_bpe   # ← webbot 전용 코드가 아니라 storybot 재사용!

merge_rules = train_bpe("webbot/owt_train.txt", vocab_size=50000,
                         num_processes=8, num_chunks=64)

코드 재사용 지도

1
CodeBot: 모든 것을 처음부터 직접 구현 (원리 학습이 목적)
2
StoryBot: model.py·tokenizer.py 모두 자체적으로 개선(RoPE 등 추가, BPE 최적화)
3
WebBot: model.py는 GQA를 더해 직접 확장하지만, tokenizer.py는 이미 검증된 storybot 것을 그대로 재사용
🏗️ 비유

세 프로젝트의 관계는 신입 개발자(CodeBot: 모든 걸 배우려고 직접 구현) → 실무자(StoryBot: 검증된 패턴으로 개선) → 팀 프로젝트(WebBot: 잘 만든 모듈은 그대로 가져다 쓰고, 새로운 부분에만 집중)로 성장하는 과정과 닮았습니다.

직접 실행해보기

각 프로젝트 폴더에서 다음 순서로 실행하면 처음부터 끝까지 재현할 수 있습니다.

# 1) 데이터·체크포인트 다운로드 (Mac/Linux)
bash codebot/download.sh      # 또는 storybot/, webbot/

# 2) (직접 학습 대신) 이미 학습된 체크포인트로 건너뛰기
# download.sh 안의 주석 처리된 wget 줄을 해제하면
# model_pretrain.pt / model_sft.pt / model_dpo.pt 등을 바로 받을 수 있음

# 3) 대화해보기
python ch03/04_chat.py        # CodeBot

학습에 시간이 오래 걸린다면, download.sh의 주석을 풀어 사전 학습된 체크포인트를 받아 SFT·DPO·생성 단계부터 바로 실습할 수 있습니다.

정리

부록 핵심 요약

  • 세 프로젝트는 model.py · tokenizer.py · utils.py라는 같은 구조를 공유
  • model.py는 2장 GPT-2를 뼈대로, 5장·8장의 부품을 점점 더해가며 진화
  • tokenizer.py는 1장 → 4장으로 최적화되고, WebBot은 아예 storybot 것을 재사용 — 검증된 코드는 다시 만들지 않는 것이 좋은 엔지니어링
  • 각 프로젝트의 실행 파이프라인(다운로드 → 토크나이저 → 인코딩 → 학습 → 생성)은 형태가 같고 규모만 다름
🎓 여기까지

0장의 "LLM은 토크나이저·모델·학습으로 이루어진다"는 큰 그림이, 실제 코드 3세트로 어떻게 구현되는지 확인했습니다. 이제 이 저장소의 어떤 파일을 열어도 "이게 몇 장, 어떤 개념에서 왔는지" 스스로 짚어낼 수 있을 것입니다.

QUIZ 1

webbot 폴더에 tokenizer.py가 없는 이유는?

정답: 두 번째. ch07/01_bpe_train.py는 storybot.tokenizer의 train_bpe를 그대로 import해서 사용합니다.
QUIZ 2

CodeBot과 달리 WebBot 파이프라인에 빠져 있는 학습 단계는?

정답: 두 번째. WebBot은 대규모 사전 학습 효율화에 집중하는 도전편이라, SFT·RL 단계는 다루지 않습니다.
