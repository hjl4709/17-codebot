9.1 기울기 누적

한 번에 못 옮기면, 나눠 옮긴 뒤 한꺼번에 정리

📦 비유

GPU 메모리 한계 때문에 한 번에 큰 배치를 처리할 수 없을 때가 많습니다. 기울기 누적은 작은 배치(micro-batch)를 여러 번 처리하면서 기울기를 계속 더해두기만 하다가, 마지막에 한 번만 파라미터를 갱신합니다 — 큰 짐을 한 번에 옮길 힘이 없을 때 여러 번 나눠 옮긴 뒤, 다 모이면 한꺼번에 정리하는 것과 같습니다. 결과적으로 훨씬 큰 "유효 배치 크기"로 학습한 것과 같은 효과를 냅니다.

optimizer.zero_grad()
for micro_step in range(accumulation_steps):    # 예: 4번 나눠서
    loss = compute_loss(micro_batch) / accumulation_steps
    loss.backward()                                # 기울기를 계속 누적
optimizer.step()                                    # 마지막에 한 번만 갱신
# 유효 배치 크기 = micro_batch_size × accumulation_steps (WebBot: 32 × 4 = 128)
9.2 기울기 체크포인트

모든 풀이 과정 대신 핵심 지점만 메모하기

📝 비유

역전파를 하려면 순전파 때의 중간 계산값을 모두 기억해야 하는데, 층이 깊을수록 메모리 부담이 커집니다. 기울기 체크포인트는 중간 결과를 다 저장하지 않고 일부 지점만 메모해뒀다가, 필요할 때 그 지점부터 다시 계산합니다 — 풀이 과정을 한 줄 한 줄 다 받아 적는 대신 핵심 단계만 메모해두고, 필요하면 그 지점부터 다시 풀어보는 것과 같습니다. 메모리는 절약되지만, 다시 계산하는 만큼 속도는 다소 느려지는 트레이드오프가 있습니다.

이 저장소의 실습 코드에는 포함되어 있지 않지만, 매우 큰 모델을 제한된 GPU 메모리로 학습할 때 널리 쓰이는 기법입니다.

9.3 분산 학습 (DDP)

같은 문제집을 여러 명이 나눠 풀고, 답을 맞춰보기

👥 비유

GPU 여러 대에 모델을 각각 복제해두고, 각 GPU가 서로 다른 데이터 배치를 동시에 처리합니다. 각자 계산한 기울기를 주기적으로 서로 맞춰(동기화) 모든 GPU가 같은 방향으로 함께 나아가게 합니다 — 같은 문제집을 여러 명이 나눠 풀고, 각자 푼 답을 모아 평균 내서 다 같이 다음 단계로 넘어가는 스터디 그룹과 같습니다.

from torch.nn.parallel import DistributedDataParallel as DDP

model = DDP(model, device_ids=[local_rank])   # GPU마다 모델 복제
# 각 GPU가 다른 배치를 처리하고, backward() 시점에 기울기를 자동으로 평균
9.4 ZeRO

모두가 책 전체를 복사하지 않고, 나눠 갖고 필요할 때 빌리기

📚 비유

DDP에서는 모든 GPU가 모델 전체(파라미터+옵티마이저 상태)의 사본을 각자 갖고 있어 메모리 낭비가 있습니다. ZeRO는 이 상태들을 GPU들끼리 나눠서 보관하고, 계산에 필요한 순간에만 서로 주고받습니다 — 스터디 그룹 전원이 두꺼운 참고서 전체를 각자 사는 대신, 챕터를 나눠 갖고 필요할 때 서로 빌려보는 것과 같아 메모리를 훨씬 아낄 수 있습니다.

이 저장소는 DDP까지만 다루지만, 더 큰 모델일수록 ZeRO(또는 FSDP) 같은 상태 분산 기법이 필수가 됩니다.

9.5 Muon 옵티마이저

AdamW 다음 세대의 새로운 시도

🌀 비유

Muon은 6장의 AdamW와 달리, 파라미터 갱신 방향을 행렬 구조에 맞게 다듬는(직교화) 방식을 사용하는 비교적 최신 옵티마이저입니다. 방향의 "결"을 가지런히 정리해 갱신하는 느낌으로, 특정 대형 모델 학습에서 AdamW보다 더 빠른 수렴을 보였다는 연구 결과가 있습니다 — 아직 활발히 연구되는 최신 기법으로, 이 책에서는 개념만 소개합니다.

9.6 Weights & Biases

실험을 대신 기록해주는 자동 비서

🗒️ 비유

여러 GPU로 며칠씩 걸리는 학습을 매번 터미널 로그로 지켜보긴 어렵습니다. W&B(Weights & Biases)는 손실 곡선, 학습률, 하이퍼파라미터를 실시간 대시보드에 자동 기록해주는 비서 역할을 합니다 — 어디서든 웹 브라우저로 실험 진행 상황을 확인할 수 있습니다.

wandb.init(project='webbot-pretrain', config={...})

for step in range(max_iters):
    ...
    wandb.log({'train/loss': train_loss, 'train/lr': lr}, step=step)  # 매 스텝 기록

QUIZ 1

기울기 누적(gradient accumulation)의 목적은?

정답: 두 번째. 작은 배치 여러 개의 기울기를 누적한 뒤 한 번만 갱신해, 메모리는 적게 쓰면서 큰 배치와 같은 효과를 냅니다.
QUIZ 2

DDP와 ZeRO의 가장 큰 차이는?

정답: 두 번째. DDP는 각 GPU가 전체 모델 사본을 갖지만, ZeRO는 파라미터·옵티마이저 상태를 GPU들끼리 나눠 가져 메모리를 절약합니다.
